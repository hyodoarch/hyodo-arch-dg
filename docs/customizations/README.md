既存機能の説明は [開発・公開手順](../local-development.md) と各docsを参照する。Vaultが利用できる場合は `_メモ置場/サイト運用の説明書/アップデート時に上書きされる可能性のあるファイル.md` が従来の機能別台帳。台帳には変更概要とこの記録への参照を残し、詳しい復元手順を二重管理しない。

## 更新・記録の手順

1. `AGENTS.md` に従ってGit状態・originを確認する。既存変更や未送信コミットを保護し、上流版で丸ごと上書きしない。
2. 変更対象に関係する記録を読み、標準ファイルへの直接変更と、独自追加・ユーザー拡張を区別して比較する。独自追加は通常残るが、フォルダー置換・再取得・読込仕様変更に対する保証ではない。
3. 必要な独自部分を新バージョンに再統合する。記録には目的、ルート相対パス、必要なコードと理由、上書きの契機・消失時の影響、確認方法、復元元・手順、確認日を記す。
4. Node22で `npm test` と `npm run build`、各記録の検証を実行する。検証処理やnpm scripts自体も更新で失われうるため、成功ログだけでなく登録も確認する。
5. ユーザー確認後にcommit・pushし、該当コミットのCloudflareデプロイ成功と公開URLを確認する。ローカル検証・GitHub保存・公開成功は分けて報告する。

docsとAGENTS.mdも独自資料として維持する。全体置換で失った場合は、このリポジトリのGit履歴とVaultの台帳から該当部分を復元する。
